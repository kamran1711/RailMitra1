RAILFLOW AI - LIVE TRAIN TRACKING & RAILRADAR INTEGRATION GUIDE
Architecture, Feasibility, Trade-Offs, and Implementation Steps
================================================================================

1. FEASIBILITY ANALYSIS: CAN WE USE RAILRADAR?
--------------------------------------------------------------------------------
YES. RailRadar (and equivalent Indian Railway developer APIs such as 
railradar.in, IndianRailAPI, or RapidAPI IRCTC endpoints) can be integrated 
directly into the RailFlow AI backend.

RailRadar exposes RESTful endpoints for:
1. Live Train Running Status:
   - Current/last passed station code (e.g., ALJN, TDL, GZB)
   - Real-time delay in minutes (e.g., late by 14 mins)
   - Actual vs. scheduled arrival and departure timestamps
   - Current operational status (e.g., "Departed", "Approaching", "At Platform")
2. Live Station Arrival/Departure Boards:
   - Expected trains reaching a station junction within the next 2-4 hours
3. Live PNR Enquiry:
   - Real-time coach, berth, class, and chart confirmation status


2. VALUE ASSESSMENT: IS THERE ANY USE?
--------------------------------------------------------------------------------

A. HIGH-VALUE BENEFITS:
1. Authentic Ground-Truth Delays:
   Replaces initial static delay values (e.g., default_delay = 14) with real-world
   operational delays occurring right now on Indian Railways tracks.
2. Authentic PNR Status Resolution:
   Enables live passenger lookup for any authentic 10-digit PNR rather than
   relying exclusively on mock entries.
3. The Winning Hybrid Pitch (SIH / Hackathons / Rail Evaluators):
   - What RailRadar/NTES gives:
     Raw, descriptive, historic data: "Train 12723 is late by 18 mins at Aligarh."
     It does NOT explain why, nor does it predict downstream junction ripple delays.
   - What RailFlow AI adds on top:
     Takes that live ground-truth delay and enriches it with:
     * LightGBM dynamic ETA prediction factoring in upcoming route congestion
     * SHAP Explainable AI attribution badges (Fog, Freight Headway, Junction Locks)
     * Section Controller "What-If" decision simulation and platform conflict alerts

B. INHERENT LIMITATIONS & HOW TO SOLVE THEM:
1. Milestone Updates vs. Continuous GPS:
   - Limitation: Public railway APIs pull from NTES, which updates primarily when
     trains cross station block stations. They do NOT provide 1-second continuous
     locomotive GPS telemetry.
   - Solution: RailRadar provides the current station milestone and delay;
     RailFlow AI's track_network.py and telemetry_engine.py continue kinematic
     interpolation between stations so the Leaflet map stays smoothly animated.
2. Rate Limits & Latency:
   - Limitation: Free/developer tier APIs typically cap queries (e.g., 50-100/day
     or strict per-minute limits). Polling external APIs every 2.5 seconds will
     exhaust your quota in minutes.
   - Solution: Run a background worker that polls external APIs every 60 to 120
     seconds and stores responses in an in-memory cache. The 2.5-second WebSocket
     loop reads from the local cache.
3. Freight Trains Are Confidential:
   - Limitation: Indian Railways does not publish freight train telemetry (e.g., F-809)
     on public passenger portals; freight tracking is restricted to internal FOIS.
   - Solution: Keep passenger trains (AP Express, Vande Bharat, Rajdhani) on live API
     sync, while freight trains remain simulated to showcase mixed-traffic precedence.

4. STEP-BY-STEP IMPLEMENTATION GUIDE
--------------------------------------------------------------------------------

STEP 1: INSTALL HTTP ASYNC CLIENT
---------------------------------
Ensure httpx is installed for non-blocking API calls:
  pip install httpx

STEP 2: CREATE LIVE TRACKING SERVICE MODULE
-------------------------------------------
Create file: backend/services/live_tracker.py

```python
import os
import httpx
from typing import Dict, Optional

RAILRADAR_API_KEY = os.getenv("RAILRADAR_API_KEY", "")
BASE_URL = os.getenv("RAILRADAR_BASE_URL", "https://api.railradar.in/v1")

class LiveTrainTracker:
    def __init__(self):
        # Cache keyed by train_no: {"current_station": str, "delay_min": float, ...}
        self.cache: Dict[str, Dict] = {}

    async def fetch_live_status(self, train_no: str) -> Optional[Dict]:
        """
        Fetches live train running status.
        Falls back to local cache or simulated baseline if API is unavailable.
        """
        if not RAILRADAR_API_KEY:
            # Running in offline / evaluation simulation mode
            return None

        try:
            async with httpx.AsyncClient(timeout=6.0) as client:
                headers = {
                    "Authorization": f"Bearer {RAILRADAR_API_KEY}",
                    "Accept": "application/json"
                }
                response = await client.get(
                    f"{BASE_URL}/trains/{train_no}/live",
                    headers=headers
                )
                if response.status_code == 200:
                    data = response.json()
                    parsed = {
                        "train_no": train_no,
                        "current_station": data.get("current_station_code"),
                        "delay_min": float(data.get("delay_minutes", 0)),
                        "speed_kmh": float(data.get("speed_kmh", 80)),
                        "last_reported_time": data.get("timestamp"),
                    }
                    self.cache[train_no] = parsed
                    return parsed
        except Exception as err:
            print(f"[LiveTracker] Warning: External API query failed for {train_no}: {err}")

        # Return last cached status if network fails
        return self.cache.get(train_no)

live_tracker = LiveTrainTracker()
```

STEP 3: INTEGRATE PERIODIC POLLING IN TELEMETRY ENGINE
------------------------------------------------------
In file: backend/simulation/telemetry_engine.py

Add the external polling task:

```python
from backend.services.live_tracker import live_tracker

# Inside TelemetryEngine class:
async def run_external_sync_loop(self):
    """
    Periodically queries live external APIs every 60 seconds without
    blocking or slowing down the 2.5s WebSocket broadcast loop.
    """
    while self.running:
        for train in self.active_trains:
            t_no = train["train_no"]
            # Exclude simulated freight trains
            if t_no.startswith("F-"):
                continue

            live_info = await live_tracker.fetch_live_status(t_no)
            if live_info:
                # Update ground-truth delay from real railway API
                train["default_delay"] = live_info["delay_min"]
                if live_info["current_station"]:
                    train["current_section"] = f"{live_info['current_station']}-NEXT"

        # Wait 60 seconds before next external API call
        await asyncio.sleep(60.0)
```

STEP 4: ORCHESTRATE BACKGROUND TASKS IN APPLICATION LIFESPAN
------------------------------------------------------------
In file: backend/main.py

Update the lifespan manager to run both the 2.5s animation and 60s sync task:

```python
@asynccontextmanager
async def lifespan(app: FastAPI):
    # 1. High-frequency 2.5s train movement and WebSocket loop
    sim_task = asyncio.create_task(telemetry_engine.run_simulation_loop())
    # 2. Low-frequency 60s external API synchronization loop
    sync_task = asyncio.create_task(telemetry_engine.run_external_sync_loop())
    print("[RailFlow AI] Telemetry engine and live sync worker initialized.")
    yield
    telemetry_engine.running = False
    sim_task.cancel()
    sync_task.cancel()
    print("[RailFlow AI] System shutdown clean.")
```

6. FINAL RECOMMENDATION
--------------------------------------------------------------------------------
- For Hackathon/SIH Demonstrations:
  Use a hybrid mode. Configure RailRadar for 2-3 prominent express trains (such as
  12723 AP Express and 22436 Vande Bharat). If an API key is absent or offline,
  the system automatically falls back to local simulation without crashing.
- For Production/Rail Authority Deployment:
  Interface directly with Indian Railways CRIS RTIS (Real-time Train Information
  System) locomotive GPS device streams via Kafka or MQTT enterprise brokers.
